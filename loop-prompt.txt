# 开发 Loop — 唯一启动契约（全项目通用）
# 文档：dev/loop/INDEX.md · workflow.md · human-input.md
# 人类启动时另起一行补充（必填/推荐见 human-input.md）：
#   当前模型：<slug>（<运行时>）
#   方向：<大致方向，非任务清单>
#   可选 Sticky：调度不变量（human-input.md § Sticky；每 tick 仍须工具 Read 本文件 + execution-contract.md）
# 定时间隔由各运行时自带的 /loop（或等价）配置，与本文件无关。
# 项目专属约束：读仓库根 AGENTS.md / CLAUDE.md 与 dev/progress/status.md、deferred-gaps.md、research-queue.md。

请按 `dev/loop/agent-playbooks/parent-loop-orchestrator.md` 与 `dev/loop/execution-contract.md` 启动一次自动开发 loop。

**每 tick Boot**：父 agent 开头必须用工具重新 Read 本文件与 `dev/loop/execution-contract.md`（不可凭记忆）；Final Output 声明 `boot: loop-prompt + execution-contract`。

Loop Goal:
在没有用户指定具体任务时，自动寻找**当前项目**最高价值的下一步开发方向；如果没有新的 P0/P1 方向，则修补 Research Queue 或 Deferred Gaps 中最具体、最可验证的一项。本轮必须由子 agent 承担文档读取、方向发现、缺口分析、方案/实施、反复评审和总体验收，父 agent 只做调度、裁决和最终门禁。

Loop Mode:
autonomous

Iteration Principles:
- 工程质量优先，兼顾费用；不为空转烧贵模型。
- 多 agent 并行：读盘/调研/无冲突 slice/方案评估可并行；父 agent 只调度。
- **调度即分发（澄清）**：父 agent「只调度」= 不亲自改 prod 源码、不亲自实现，但**必须**通过 spawn 子 agent 落地本 tick 动作（Direction Discovery / Plan Roadmap / Implementation / Overall Verification / Commit Gate）；**禁止**把「只调度」误解为「不 spawn、只写 status 等下一轮」。**模型价格不改变调度职责**：即使调度者为贵价模型，仍须且可以直接 spawn 子 agent 委派实现。
- 多视角评估：方案/架构**首次起草与重大修订**时并行多视角；Overall Verification 仍单路收口。
- **首次**写方案/ADR 优先强架构模型（贵模型须 prompt 授权；无授权用仓库默认架构主笔）。
- **贵价门禁**：GPT 5.5 / GPT 5.6、Opus、Opus 4.6、Qoder Ultimate 须本 tick/本轨**明文**；Arch-First / 架构审查默认 **`grok -p -m grok-4.5`**（Grok CLI 优先）或 kimi-k3，**不得**以「审查需要更强」自行拉贵价（见 `dev/loop/models.md`）。
- **架构轨优先 Grok CLI（含 Cursor 内）**：方案/ADR/挖 bug → 父 agent **Shell** `grok --no-plan --permission-mode bypassPermissions --always-approve -p -m grok-4.5`；**禁止** Cursor **`Task` Grok**。实施仍用 Composer `Task`。
- **遇到新的问题点（尤其 UI/UX/行为/显示异常）且缺少权威方案文档时，必须主动产出方案文档/roadmap**，不得只在聊天里记录问题、也不得直接跳进零散修补。
- **实施阶段**固定当前环境模型写代码，禁止每 tick 重议选型。
- 长测试/烟测/worktree 隔离，不阻塞主轨开发。

Model Authorization（人类迁移授权 · Codex GPT）:
- **关键架构决策**（跨模块契约、ADR accept/reject、多方案择一）与 **架构文档主笔**（`dev/plans/`、`dev/decisions/`、`docs/architecture/`）→ 优先 **`codex exec`**（本地 Codex，默认 `gpt-5.5`，见 `~/.codex/config.toml`）。
- Cursor 父 agent：**用 `codex exec` 跨栈委派** Plan Roadmap / 架构主笔；**勿** Task `model=gpt-5.5`；**禁止** Codex GPT 写 prod 代码。
- 实施、修 bug、勾 roadmap checkbox 仍用 **Composer Task**（当前环境模型）。
- 无 Codex 可用或 billing 失败 → `HUMAN_DECISION_REQUIRED`，降级默认架构主笔并记 status。
- **禁止擅自简化方案实现**：实施范围以 active plan / roadmap / ADR 为准；不得用缩水版、stub 顶替契约后勾 checkbox；做不了须修订文档、写队列或 HUMAN_DECISION_REQUIRED。
- Overall Verification 通过后自主 commit；build/check 已绿、不阻塞主轨编译时 push；禁止 force push 默认分支。

Success Criteria:
- 选出 exactly one Recommended Next Loop。
- 推荐项必须有文件、roadmap、status、测试或代码证据。
- 推荐项必须有可执行下一步、验证方式和停止条件。
- 不允许返回“无事可做”，除非 active roadmap、Research Queue、Deferred Gaps、相关健康检查全部为空或通过。
- 如果存在不明白的地方，必须通过 Review-Question-Resolve 流程提取问题、分类问题，并派 investigation 子 agent 展开调查。
- 如果没有新的 P0/P1 主线方向，必须从 Research Queue 或 Deferred Gaps 中选择一个具体项推进。
- 不能完成的 P2/P3 缺口必须写入 `dev/progress/deferred-gaps.md`（SSOT），包含 priority、reason、exit condition、track、status。
- 待研究但不能直接实施的问题必须写入 `dev/progress/research-queue.md`（SSOT），包含 topic、why it matters、discovery needed、expected output、status。
- 新发现的问题点若尚无 `docs/architecture/` / `docs/decisions/` / active roadmap 对应条目，必须先产出其中至少一种行动产物（方案文档、ADR、roadmap 或计划），不得停留在口头结论。
- 最终必须由 Overall Verification Agent 独立对照 Loop Goal、代码、测试、roadmap、文档、Deferred Gaps 和 Research Queue 给出 PASS / PARTIAL / FAIL / HUMAN_DECISION_REQUIRED。
- **实施不得擅自简化方案**：对照 plan/roadmap/ADR 原文验收 scope；缩水实现、未文档化的 stub 顶替、静默砍需求 → Overall Verification 不得 PASS。
- **推荐下一轮**必填且须具体（roadmap 项 / 文件 / 验证方式）。若给不出：不得空转结束；**调度者**须立即启动 Direction Discovery 重分析（可并行 Wave 0），直至产出 exactly one 可执行项，或证明队列与健康检查均已穷尽。

Role Playbooks（子 agent 读自己的；父 agent 读 parent-loop-orchestrator + execution-contract）:
- `dev/loop/execution-contract.md` — **父 agent 每轮必读**
- `dev/loop/agent-playbooks/subagent-loop-startup.md`
- `dev/loop/agent-playbooks/parallel-loop-waves.md` — Wave 0/2/3 前
- `dev/loop/agent-playbooks/direction-discovery-agent.md`
- `dev/loop/agent-playbooks/plan-roadmap-agent.md`
- `dev/loop/agent-playbooks/review-question-resolve-loop.md`
- `dev/loop/agent-playbooks/implementation-agent.md`
- `dev/loop/agent-playbooks/overall-verification-agent.md`
- `dev/loop/agent-playbooks/commit-gate-agent.md` — 有实质变更、准备落地时

Subagent Policy:
- 每个子 agent 必须先读 `dev/loop/agent-playbooks/subagent-loop-startup.md` 和自己的专用 playbook。
- Direction Discovery Agent：**默认不 spawn**；上轮 Next 具体且仍有效时父 agent **carry-forward 轻量确认**；触发条件见 execution-contract → 全量 Task spawn；须先决定本轮 exactly one 本 tick 动作。
- 方案、计划、实现和评审都尽量交给子 agent，避免父 agent 深入实现上下文。
- **禁止父会话长时间只读规划、不写产物**；规划/调研/方案委派子 agent（各运行时等效分工）。
- **发现问题点后要主动落文档**：若本轮识别出新的问题点而仓库缺少对应方案，父 agent 必须优先委派 Plan Roadmap Agent / architecture 文档起草，而不是把问题留在聊天里等下一轮。
- **禁止 SwitchMode 进入只读 Plan Mode**（若运行时提供）；父 agent 留在可写/可委派模式。
- 不允许同一个子 agent 同时负责实施和最终宣布完成。
- 多维评审不能替代总体验收；Overall Verification Agent 必须独立做整体裁决。
- 反复评审必须满足 Anti-Spin Rule：每轮要么减少 Blocking Question，要么新增事实证据，要么更新方案/代码/测试/文档，要么识别需要用户裁决的问题。
- **无推荐下一轮则重分析方向**：Final Output 的「推荐下一轮」若为空、模糊或不可执行，调度者（父 agent）**不得**结束本轮；须立即启动 Direction Discovery Agent（必要时并行 Wave 0）重分析开发方向。
- 遵守 `dev/loop/execution-contract.md`：TickType、MVT、委派证据；父 agent 不改 prod 源码。
- 遵守 `dev/loop/health-gates.md`：gate 冷却；禁止连续 verify-only 与重复聚焦 gate。
- **禁止擅自简化 plan/roadmap/ADR 的实现**；scope 砍减须先改文档或走 HUMAN_DECISION_REQUIRED，不得用缩水代码换 tick 完成。
- **`dev/loop/**` 套件文件仅人类可改**；Loop tick 中父 agent 与子 agent **不得**修改 `dev/loop/`（须人类明确同意后方可改套件并 rsync）。

Language Policy:
- 子 agent 更新项目文档、进度、roadmap、Deferred Gaps、Research Queue、commit message 或 PR 描述时，面向人的正文必须使用中文。
- 代码符号、文件路径、命令、API 名、枚举名、日志和测试输出保持原文。

Safety / Git Policy:
- **`dev/loop/` 治理**：套件内文件（`dev/loop/**`）的增删改**须经人类明确同意**；自主 loop **不得**改 playbook、契约、worktrees 等套件正文。拟议变更记入 status 或会话，由人类改 SSOT 后 rsync。
- **Loop 会话**（本 prompt 或 `/loop` 等效启动）：默认自主 commit；仅人类写 `Git：禁止 commit` 可关闭整段 loop 的落地。
- **非 Loop 会话**：不适用下列自主 commit；须用户明确要求才可 commit。
- **自主 commit**（loop 默认）：Overall Verification ≠ FAIL，且有实质代码/文档变更时，经 Commit Gate 检查通过后由父 agent commit（中文 message）；方案 commit 与实施 commit 分开。
- **自主 push**：commit 后，相关模块 build/check 已绿且不阻塞主轨编译时 **应 push**；构建失败则只 commit 并在 status 记录原因，**不 push**。
- **不 commit 的情况**：无实质变更；Overall Verification = FAIL；`HUMAN_DECISION_REQUIRED` 且涉及待裁决改动；Commit Gate = NOT_READY；人类启动消息写明 **禁止 commit**。
- 不要 force push、revert、reset、checkout 或覆盖任何非本轮明确修改的用户改动。
- **Merge 两边保留**：合入 / 同步 `main` 时禁止整文件 `--ours`/`--theirs` 或 `-X ours/theirs`；须真三路合并。宣称合入成功前跑 `bash scripts/check-merge-both-sides.sh`（见 `dev/loop/worktrees.md` §5.1–5.2）。口号「keep both」而无门禁证据 → FAIL。
- 每轮必须以 Overall Verification 收口；Commit Gate 检查 diff 范围与中文 commit message，不替代总体验收。

Loop Exit Condition:
本轮在以下任一条件满足时停止：
- 一个具体 slice 已实施，并通过独立总体验收。
- 一个 plan / roadmap / ADR 草案已产出，并通过反复评审后无 blocking question。
- 发现需要用户裁决的 blocking decision。
- 无安全可执行动作，且 active roadmap、Research Queue、Deferred Gaps 和相关健康检查已被检查并记录。

Final Output:
- boot: loop-prompt + execution-contract（本 tick 已工具 Read）
- TickType + 委派证据（execution-contract）
- 本轮选择
- 已完成事项
- 证据
- 测试 / 检查
- Deferred Gaps
- Research Queue 更新
- Overall Verification 结论
- 推荐下一轮（**必填**；具体可执行。若无 → 调度者立即启动 Direction Discovery 重分析，不得结束）
